مساله#

در برنامه‌‌ام نمی‌خواستم که فقط فایل‌های مربوط به BPMN را ذخیره کنم، بلکه می‌خواستم کاربر بتواند آن را در محیط Oracle Apex مشاهده و ویرایش کند، Activityهای آن را استخراج کرد و …

💡 در پروژه‌ای که سال‌های قبل با .NET برای مدیریت فرایندهای سازمانی نوشته بودم، این امکان وجود داشت که فعالیت‌های موجود در نمودار به پست‌های سازمانی، متصل شوند.
بدین ترتیب مشخص می‌شود هر پست سازمانی، در چه فرایندهایی است، چه وظایف و چه نقش‌هایی دارد، و یا در صورت حذف یک نقش چه وظایفی متاثر می‌شوند و …

برای استفاده از BPMN در Oracle Apex می‌توان از افزونه‌ای به نام Flows for APEX استفاده کرد که یک Workflow Engine قدرتمند با کلی امکانات است.

📌 اما من نمی‌خواستم برای شکار خرگوش از توپ جنگی استفاده کنم!!!

بنابراین از BPMN.IO برای اینکار استفاده کردم.

پس از انجام مراحلی که در ادامه خواهید دید، در نهایت امکانات زیر را بدست می‌آوریم:

  • بارگذاری فایل‌ها BPMN
  • خروجی با فرمت: XML, SVG, PNG, JPG, WEBP
  • ثبت در دیتابیس
  • PL/SQL برای استخراج تمامی objectها، activityها و … از فایل BPMN

معرفی#

BPMN#

Business Process Model and Notation
BPMN استاندارد جهانی برای مدل‌سازی و نمایش فرآیندهای کسب‌وکار است که به سازمان‌ها امکان می‌دهد مراحل انجام کار، ترتیب فعالیت‌ها، نقاط تصمیم‌گیری و تعاملات میان افراد و واحدهای سازمانی را با استفاده از علائم گرافیکی ترسیم کنند و نمایش دهند.

🔔 قالب استاندارد ذخیره‌سازی مدل‌های BPMN، فرمت XML است.

نرم‌افزارهایی مانند Camunda و Bizagi Modeler و همچنین افزونه‌هایی در VS Code امکان کار با این فایل‌ها را فراهم می‌کنند.


Flows for APEX#

Flows for APEX یک افزونه متن‌باز برای Oracle APEX است که امکان طراحی، اجرا و مدیریت گردش کار (Workflow) را در برنامه‌های APEX فراهم می‌کند.

  • مدل‌سازی گردش کار بر اساس استاندارد BPMN
  • اجرای فرایندها و مدیریت وضعیت آن‌ها
  • تخصیص وظایف به کاربران
  • مدیریت مراحل و مسیرهای اجرای فرایند
  • پشتیبانی از تأیید و رد درخواست‌ها
  • پیگیری وضعیت و تاریخچه اجرای فرایندها
  • یکپارچگی با Oracle APEX و پایگاه داده Oracle

BPMN.IO#

BPMN.IO مجموعه‌ای از کتابخانه‌های جاوا اسکریپت (JavaScript):

  • امکان ایجاد و نمایش مدل‌ها در مرورگر
  • ایجاد و نمایش نمودارهای BPMN
  • import/export از مدل‌ها در قالب XML
  • توسعه‌پذیری از طریق کتابخانه‌های JavaScript
  • …

پیاده‌سازی در APEX#

Source#

در اینجا ، می‌توانید سورس مربوطه شامل صفحه، فایل‌های js و package مورد نیاز را مشاهده و دانلود کنید. تمامی فایل‌هایی که در ادامه توضیح خواهم داد در این مخزن وجود دارند.

فایل‌های مورد نیاز#

  1. bpmn-modeler.development.js ( دریافت )
    هسته Modeler است و برای نمایش و ویرایش دیاگرام استفاده می‌شود. ایجاد Task، Gateway، اتصال‌ها، جابه‌جایی عناصر و…
  2. diagram-js.css ( دریافت )
    فایل CSS کتابخانه diagram-js است که ظاهر و نحوه نمایش اجزای نمودار، ابزارهای تعاملی و عناصر رابط کاربری آن را مشخص می‌کند.
  3. bpmn-embedded.css ( دریافت )
    این فایلcss فونت آیکون‌های BPMN است که در کتابخانه bpmn-js استفاده می‌شود. این فونت شامل نمادهای گرافیکی عناصر BPMN است و نمایش صحیح آیکون‌هایی مانند event, activity, gateway و … را امکان‌پذیر می‌کند.
  • برای اینکه از آخرین نسخه فایل‌ها استفاده کنید، کافی است شماره نسخه را از لینک حذف کنید.
  • سایت دیگر برای دانلود فایل‌ها unpkg

به خاطر اینکه برنامه‌ها معمولا درون سازمانی هستند و ممکن است به اینترنت دسترسی نداشته باشند، این فایل‌ها را دانلود و در قسمت Static Application Files بارگذاری می‌کنیم. من آن‌ها را در پوشه‌ی bpmn ذخیره کردم.

  1. my-bpmn.js ( دریافت )
    این فایلی است که تمام ‌متدهای لازم را در آن نوشته‌ام که با هر صفحه‌ی وبی (web) قابل استفاده خواهد بود و وابسته به Oracle APEX نیست.

در این فایل از شی window جهت ایجاد فضای نام bpmn استفاده شده است.

🔔 شی window

در JavaScript، شی window نماینده‌ی محیط سراسری مرورگر است. با تعریف window.bpmn، یک فضای نام برای نگهداری متغیرها و توابع مرتبط با BPMN ایجاد می‌کنیم. به این ترتیب، به‌جای تعریف متغیرهای مستقل، آن‌ها را در قالب یک شی سازمان‌دهی می‌کنیم و احتمال تداخل نام‌ها با سایر فایل‌های JavaScript کاهش می‌یابد.

حالت دیگر استفاده مستقیم از متدها در قسمت Function and Global Variable Declaration است که می‌توانید از اینجا این فایل را دانلود کنید، ولی پیشنهاد من همان مورد قبلی است. در این فایل من برای متدها از پیشوند bpmn_ استفاده کرده‌ام.

متدها my-bpmn.js#

برای استفاده از این متدها باید از فضای نام (namespace) bpmn استفاده شود.

  • init: اختصاص المنت (element) برای نمایش مدل
  • new: ایجاد دیاگرام جدید
  • readFile: خواندن فایل BPMN و برگشت نام فایل و محتویات آن
  • load: بارگذاری دیاگرام با استفاده از قالب xml
  • exportXML: ارسال خروجی دیاگرام به یک المنت. دراینجا آیتم اپکس
  • downloadXML: دانلود فایل با فرمت xml
  • downloadSVG: دانلود فایل با فرمت svg
  • downloadImage: دانلود تصویر با فرمت دلخواه (png, jpg, webp)

و دو مورد آخر که متدهای بالا از آن‌ها استفاده خواهند کرد:

  • svgToImage: تبدیل فرمت svg به image در زمان تبدیل به فرمت‌های تصویری
  • downloadBlob: تبدیل خروجی به فایل قابل دانلود

🔔 روند تبدیل بدین صورت است:

  1. تبدیل دیاگرام به svg
  2. تبدیل svg به image
  3. تبدیل خروجی (image, text) به فایل blob و فرمت مربوطه
  4. ایجاد لینک و دانلود

Upload File
برای اینکه بتوانیم محتویات یک فایل را بدون ارسال به سرور بخوانیم، از input استفاده می‌کنیم.

  • از نوع Static Content
  • آیتم FILENAME جهت درج نام فایل خوانده شده
  • Source | HTML Code:
<input type="file" id="bpmnFile" accept=".bpmn,.xml">

سپس یک Dynamic Action با رویداد Change اضافه می‌کنیم. برای قسمت True آن یک Action از نوع Execute JavaScript Code انتخاب کرده و متد خواندن فایل را در آن فراخوانی می‌کنیم:

bpmn.readFile('bpmnFile').then(({ content, filename }) => {
   
    bpmn.load(content);

    apex.item('P100012_IMPORT').setValue(content);
    //setValue(pValue, pDisplayValue, pSuppressChangeEvent) 
    apex.item('P10_FILENAME').setValue(filename, null, true);     
});

خروجی متد bpmn.readFile دو مقدار “نام فایل” و “محتویات” آن خواهد بود.

🔔 هنگام فراخوانی یک متد async، برای دسترسی به نتیجه‌ی آن باید منتظر تکمیل عملیات بمانیم. برای این کار دو روش داریم:

  • استفاده از then برای دریافت نتیجه پس از تکمیل عملیات.
  • استفاده از await درون یک تابع async و دریافت نتیجه پس از تکمیل عملیات.

🚨 Loop

اگر از setValue به شکل زیر استفاده کنیم، در یک حلقه بی‌نهایت قرار خواهیم گرفت:

apex.item('P100012_FILENAME').setValue(content);
چون آیتم FileName داخل region بارگذاری فایل قرار دارد. بعد از این که نام داخل آیتم FileName قرار می‌گیرد، رویداد change اتفاق میافتد، و یک چرخه بی‌پایان خواهیم داشت که باعث از کار افتادن دیاگرام می‌شود.
طبق JSDoc با هر set رویداد change رخ خواهد داد. برای جلوگیری از آن باید از پارامتر سوم یعنی pSuppressChangeEvent استفاده کرد.

آیتم‌های import/export#

  • آیتم IMPORT: برای نمایش محتویات xml فایل خوانده شده، استفاده می‌شود. همچنین می‌توان محتویات را در این قسمت copy/paste کرد و سپس با استفاده از دکمه Import from Item خروجی را مشاهده کرد.
  • آیتم EXPORT: با استفاده از دکمه‌ی Export to XML Item می‌توان محتویات xml نمودار را پس از ایجاد تغییرات دریافت کرد.

دکمه‌های import/export#

  • Import: با استفاده از این دکمه محتویات آیتم Import را خوانده و در نمودار نمایش می‌دهیم.
  • Export: تبدیل نمودار به فرمت xml و درج آن در آیتم Export

دکمه‌های دانلود#

در اینجا من دکمه‌های مختلفی (5 دکمه) را جهت استفاده از متدها ایجاد کرده‌ام. برای هر دکمه یک Dynamic Action از نوع Click می‌سازیم و در قسمت True آن یک Action از نوع از Execute JavaScript Code برای فراخوانی متد مربوطه ایجاد می‌کنیم.

مثلا برای دانلود فایل با فرمت webp

// نام فایل و فرمت مورد نظر
bpmn.downloadImage('diagram',bpmn.IMAGE_FORMAT.WEBP)

گزارش#

پس از ثبت نمودار در جدول، در گزارش‌های زیر محتویات نمودار انتخاب شده را مشاهده خواهیم کرد:

  • Objects: تمام اشیا استفاده شده در نمودار
  • Activities: مشاهده اطلاعات تمام فعالیت‌ها
  • Flows: مشاهده اطلاعات خطوط ارتباطی

که این موارد در 4 ستون نمایش داده می‌شوند: ID, NAME, BPMN_NAME, XML_NAME

بدست آوردن Activityها (PL/SQL)#

برای ثبت نمودار جدولی با مشخصات زیر ایجاد می‌کنیم:

create table "MY_FLOWS" (
    "ID"        number generated by default on null as identity,
    "NAME"      varchar2(200),
    "CONTENT"   clob not null,
    constraint "MY_FLOW_PK" primary key ( "ID" )
);

برای بدست آوردن محتویات نمودار، کدهای PL/SQL را در یک package به نام PKG_BPMN قرار داده‌ام، که شامل سه function است که نوع خروجی آن‌ها table است:

  • get_objects
  • get_activities
  • get_flows

get_objects#

در این متد لیست تمام اشیای مورد استفاده در نمودار را بدست میاوریم. برای این کار از xmltable استفاده می‌کنیم

select
    x.id,
    x.name,
    x.element
from xmltable('//*'
    passing v_xml
    columns
        id      varchar2(100)  path '@id',
        name    varchar2(1000) path '@name',
        element varchar2(100)  path 'local-name()'
) x
  • عبارت ‘//*’: یعنی تمام عناصر XML (با هر نامی و در هر سطحی) را انتخاب کن، به جز گره ریشه.
  • PASSING v_xml: متغیر v_xml را به‌عنوان ورودی XML در اختیار XMLTABLE قرار می‌دهد.
  • columns: در این قسمت ستون‌ها را مشخص می‌کنیم. در اینجا 3 ستون
تعریف ستون کاربرد
id varchar2(100) path '@id' مقدار ویژگی id عنصر را استخراج می‌کند.
name varchar2(1000) path '@name' مقدار ویژگی name عنصر را استخراج می‌کند.
element varchar2(100) path 'local-name()' نام خود عنصر را بدون پیشوند فضای نام استخراج می‌کند.
  • local-name: این تابع نام عنصر را بدون پیشوند فضای نام (Namespace Prefix) استخراج می‌کند. به شکل زیر هم می‌توان استفاده کرد:
local-name(.)

برای نمونه اگر یک عنصر به این شکل باشد

<bpmn:task id="Task_1" name="Check Order"/>

خروجی یک رکورد با محتویات زیر را خواهد بود:

  • id: Task_1
  • name: Check Order
  • element: task

بنابراین XMLTABLE برای هر عنصر انتخاب‌شده یک سطر تولید می‌کند و اگر عنصری مثلا ویژگی id را نداشته باشد، مقدار ستون متناظر آن NULL خواهد بود.

get_activities#

در این function از get_objects برای بدست آوردن اشیا استفاده می‌کنیم و آن‌ها را با جدولی که انواع activiyها در آن قرار دارد join ‌می‌کنیم.

 with symbols as (
               SELECT 'Task' AS name, 'task' AS xml_name FROM dual
               UNION ALL SELECT 'User Task', 'userTask' FROM dual
               UNION ALL SELECT 'Manual Task', 'manualTask' FROM dual
               UNION ALL SELECT 'Service Task', 'serviceTask' FROM dual
               UNION ALL SELECT 'Script Task', 'scriptTask' FROM dual
               UNION ALL SELECT 'Business Rule Task', 'businessRuleTask' FROM dual
               UNION ALL SELECT 'Send Task', 'sendTask' FROM dual
               UNION ALL SELECT 'Receive Task', 'receiveTask' FROM dual
               UNION ALL SELECT 'Sub-Process', 'subProcess' FROM dual
               UNION ALL SELECT 'Call Activity', 'callActivity' FROM dual
               UNION ALL SELECT 'Transaction', 'transaction' FROM dual
               UNION ALL SELECT 'Ad-Hoc Sub-Process', 'adHocSubProcess' FROM dual
           )
 select x.id, 
         x.name, 
         s.name as bpmn_name, 
         x.xml_name
 from table (get_objects(p_xml)) x
 inner join symbols s
     on x.xml_name = s.xml_name

get_flows#

این کوئری دو نوع ارتباط (ارتباطات بین اجزا) را شناسایی می‌کند:

  • sequenceFlow: ترتیب اجرای فعالیت‌ها در یک فرایند را مشخص می‌کند.
  • messageFlow: جریان پیام بین مشارکت‌کنندگان مختلف در فرایند را مشخص می‌کند.

در این متد، دو ستون source_id و target_id برای مشخص کردن عنصر آغازین و پایانی وجود دارد.

select
      x.id,
      x.name,
      x.source_id,
      x.target_id,
      lower(x.type) as type
  from xmltable(
      '//*[local-name() = "sequenceFlow"
        or local-name() = "messageFlow"]'
      passing v_xml
      columns
          id        varchar2(100)  path '@id',
          name      varchar2(1000) path '@name',
          source_id varchar2(100)  path '@sourceRef',
          target_id varchar2(100)  path '@targetRef',
          type      varchar2(100)  path 'local-name(.)'
  ) x
  where x.id is not null

منظور از عبارت زیر یعنی فقط عناصری انتخاب شوند که نام آن‌ها sequenceFlow یا messageFlow است.

[
  local-name() = "sequenceFlow"
 or local-name() = "messageFlow"
 ]

بدین ترتیب با استفاده از PKG_BPMN و متدهای داخل آن عملیات استخراج انجام می‌شود. خروجی آن‌ها در صفحه و در قسمت گزارش‌ها می‌توانید مشاهده کنید. برای نمونه در گزارش objects نحوه استفاده بدین شکل است:

select * 
from  PKG_BPMN.get_objects 
(
   (select "CONTENT"
   from my_flows
   where id = :P100012_LOV_DIAGRAM)
)
