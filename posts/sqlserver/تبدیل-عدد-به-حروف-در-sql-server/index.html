از کجا شروع شد؟#

این function را در پاییز سال 1392 نوشتم و در سایت dntips.ir منتشرش کردم.

داستانش چی بود؟ زمانی که داشتم برنامه‌ای برای محاسبه شارژ ساختمان می‌نوشتم، دوست داشتم مبلغ شارژ علاوه بر عدد به صورت حروف هم روی برگه به ازای هر واحد چاپ بشود. برای چاپ از crystal report استفاده می‌کردم که این امکان را نداشت. Stimulsoft این متد را به صورت توکار (built-in) داشت( toWord )، ولی خب آن زمان من تجربه‌ی کار با آن را نداشتم. بنابراین یا باید این متد را در C# می‌ساختم و روی خروجی سوار می‌کردم و یا در SQL Server و در زمان واکشی دیتا. من SQL Server را انتخاب کردم ببینم می‌توانم یا نه! … چالش جدید برای من 😁

بعد از این همه سال، پس از کمی بازبینی و اصلاحات در سایت خودم گذاشتم.

ورودی و خروجی#

برای اینکه محدودیت کمتری در تعداد ارقام داشته باشم، پارامتر ورودی را از نوع رشته گرفتم.

  • خروجی 2000 کاراکتر
CREATE FUNCTION dbo.fnNumberToWords_Persian
(

)
RETURNS NVARCHAR(2000)

🔔 در SQL Server نوع BIGINT حداکثر ۱۹ رقم دارد.

🔔 در SQL Server برای رشته‌های Unicode از پیشوند N استفاده می‌شود. از آنجا که متن این تابع فارسی است، رشته‌های فارسی باید به‌صورت N'...' نوشته شوند؛ مانند N'صفر'.

  • رشته null (بدون مقدار)، خالی (طول صفر) و یا فقط space است؟ مقدار null برگردان
IF LEN(ISNULL(@pNumber, '')) = 0

🔔 رفتار len با space 

select len('     ') [5char],
       len('Hamid    ') [9char]

خروجی برای 5 کاراکتر space صفر است و برای 9 کاراکتر برابر با 5 خواهد بود، زیرا تابع len کاراکترهای space آخر رشته را در نظر نمی‌گیرد.

🔔 دستور PatIndex برای یافتن یک الگو در یک متن استفاده می‌شود.

PATINDEX ( '%pattern%' , expression )

پارامتر اول الگو و پارامتر دوم عبارتی که می‌خواهیم الگو را در آن پیدا کنیم. اگر الگو را پیدا کند شماره شروع آن در عبارت را برمی‌گرداند و در غیر این صورت عدد صفر برگشت داده می‌شود.
در patern می‌توان از wildcard ها استفاده کرد.

🔔 دستور CharIndex برای پیدا کردن یک متن مشخص در متنی دیگر استفاده می‌شود.

CHARINDEX ( expressionToFind , expressionToSearch [ , start_location ] )

یک عبارت کاراکتری را درون یک عبارت کاراکتری دیگر جستجو می‌کند و در صورت یافتن، موقعیت شروع عبارت اول را برمی‌گرداند. اگر پیدا نکند مقدار صفر را برمی‌گرداند.
از wildcard ها نمی‌توان در آن استفاده کرد.

  • آیا مقدار وارد شده صفر است؟
    • مقدار صفر است، با هر تعدادی
    • مقدار صفر است، با ممیز یا بدون ممیز
    • صفر است حتی با علامت منفی
-- 0, 00, 000, 000...n
-- .0, 0.000, -.0
IF PATINDEX('%[^0.-]%', @pNumber) = 0  
		RETURN N'صفر'
  • عدد وارد شده منفی است؟ منفی را به یاد داشته باش (@negative) و علامت آن را از رشته حذف کن
-- -123 -> 123
DECLARE @Negative  AS NVARCHAR(5) = '';
	IF LEFT(@pNumber, 1) = '-'
	BEGIN
	    SET @pNumber = SUBSTRING(@pNumber, 2, LEN(@pNumber))
        -- 5 char
	    SET @Negative  = N'منفی ' 
	END
  • رشته با ممیز (.) شروع شده است؟ به اول آن یک صفر اضافه کن.
-- .123 => 0.123
IF (CHARINDEX('.', @pNumber) = 1) 
		SET @pNumber='0' + @pNumber

جداسازی قسمت صحیح از اعشاری#

در ابتدا بررسی می‌کنیم که ممیز وجود دارد یا خیر؟ اگر ممیز وجود نداشت، موقعیت آن را یک واحد بعد از آخرین کاراکتر (یعنی طول رشته) در نظر می‌گیریم تا بتوانیم عدد صحیح را کامل بدست آوریم.

-- بدست آوردن قسمت صحیح و اعشاری	
DECLARE @IntegerText NVARCHAR(100),
		@DecimalText NVARCHAR(100),
		-- اگر ممیز ندارد آن را برابر طول رشته +1 قرار بده		
		@PointPosition INT= CASE CHARINDEX('.', @pNumber) 		
								WHEN 0 THEN LEN(@pNumber) +1 
								ELSE CHARINDEX('.', @pNumber) 
							END

سپس مقدار صحیح و اعشار را بدست میاوریم.

-- از اعشار به قبل
SET @IntegerText= LEFT(@pNumber, @PointPosition - 1) 
-- از اعشار به بعد
SET @DecimalText=  SUBSTRING(@pNumber, @PointPosition + 1, LEN(@pNumber))

می‌دانیم صفرهای سمت راست اعشار بی‌ارزش هستند مثل 1.2000 بنابراین پس از بدست آوردن مقدار اعشاری، برای حذف این صفرها:

  • تمام صفرها را با space جایگزین می‌کنیم.
  • با rtrim فضاهای خالی سمت راست را حذف می‌کنیم.
  • سپس فضاهای خالی دیگر را با صفر جایگزین می‌کنیم.
-- حذف صفرهای بی ارزش ممیز
SET @DecimalText=  REPLACE(RTRIM(REPLACE(@DecimalText,'0',' ')),' ','0');

🔔 در روش قبلی من مقدار اعشاری را معکوس می‌کردم تا صفرها در ابتدا بیایند و سپس اولین عدد غیر صفر را پیدا می‌کردم و با substring یا left مقدار اعشار بدون صفر اضافه را بدست میاوردم؛ که با نظر یکی از کاربران سایت « دات ﻧﺖ ﺗﯿﭙﺲ » به روش replace که روش بهتری بود تغییر کرد.

LEFT(
   @DecimalNumber,
   LEN(@DecimalNumber) - PATINDEX('%[^0]%', REVERSE(@DecimalNumber)) + 1
)

به مقدار @IntegerText در انتهای متد نیاز داریم، بنابراین مقدار آن را به @pNumber می‌دهیم.

SET @pNumber= @IntegerText

تفکیک یکان، دهگان و صدگان#

  • با استفاده از یک حلقه عدد صحیح را سه رقم سه رقم جدا می‌کنیم
    • استفاده از تابع right
    • تا زمانی که طول عدد صحیح کمتر از 3 شود
143464565464600004000
↓
143 | 464 | 565 | 464 | 600 | 004 | 000
  • جدول @MyNumbers برای نگهداری رقم‌ها براساس ارزش مکانی
DECLARE @Number AS INT
DECLARE @MyNumbers TABLE
	(
		id   INT IDENTITY(1, 1),
		Val1 INT,
		Val2 INT,
		Val3 INT
	)

WHILE (@pNumber) <> '0'
BEGIN
	-- استخراج سه رقم انتهایی
	SET @Number= CAST(RIGHT(@pNumber, 3) AS INT)	
	
	-- تفکیک صدگان، دهگان و یکان
	INSERT INTO @MyNumbers (Val1, Val2, Val3)
	SELECT 
		--@Number / 100 * 100,
		@Number - (@Number % 100), 
		CASE 
			WHEN @Number BETWEEN 10 AND 19 THEN @Number
			ELSE (@Number % 100) - (@Number % 10) 
			--ELSE @Number / 10 * 10
		END,
		CASE 
			WHEN @Number BETWEEN 10 AND 19 THEN 0
			ELSE (@Number % 10)
		END

	-- طول عدد بیشتر از دو است	
	IF LEN(@pNumber) > 2
	    -- حذف سه رقم پردازش‌ شده از انتهای رشته
		SET @pNumber = LEFT(@pNumber, LEN(@pNumber) -3)
	ELSE
		SET @pNumber = '0'
END

به عنوان نمونه برای عدد 0001200955015 خروجی زیر را خواهیم داشت. از id این جدول برای join به جدول PositionTitle استفاده خواهیم کرد و سطر اول ارزش مکانی ندارد، برای همین در جدول PositionTitle شناسه 1 بدون مقدار است.

همانطور که در Query مشخص است برای اعداد 10 تا 19 عملیات جداسازی دهگان و یکان را انجام نمی‌دهیم و فقط باید val2 مقدار داشته باشد و برای val3 مقدار صفر شود. زیرا این‌ها اعدادی هستند که واژه‌های خاص خود را دارند.

🔔 در SQL تقسیم دو عدد صحیح خروجی صحیح خواهد داشت

155 / 100 = 1
بنابراین از روش که در کوئری کامنت کردم هم می‌توان استفاده کرد.

بدست آوردن عنوان‌ها با join#

در این قسمت اعداد بدست آمده را با جدول‌های ارزش مکانی و عنوان اعداد ترکیب می‌کنیم:

  • با استفاده از شرط سطرهایی را خواهیم داشت که جمع آن بیش از صفر باشد.
  • join با جدول @PositionTitle براساس ID.
  • برای val1, val2, val3 با جدول @NumberTitle و فیلد val آن join می‌زنیم.
  • مرتب‌سازی براساس id
  • Replace بیرونی: جایگزین کردن “دو فاصله‌ی خالی” با “یک فاصله‌ی خالی”
  • Replace داخلی: جایگزینی فاصله‌های خالی با «و»
DECLARE @Str AS NVARCHAR(2000) = '';

	SELECT @Str += REPLACE(REPLACE(
							TRIM(nt1.Title + ' ' + nt2.Title + ' ' + nt3.title)
							,' ', N' و '),'  ',' ')
	       + ' ' + pt.title + N' و '
	FROM   @MyNumbers  AS mn
	       INNER JOIN @PositionTitle pt
	            ON  pt.id = mn.id
	       INNER JOIN @NumberTitle nt1
	            ON  nt1.val = mn.Val1
	       INNER JOIN @NumberTitle nt2
	            ON  nt2.val = mn.Val2
	       INNER JOIN @NumberTitle nt3
	            ON  nt3.val = mn.Val3
	WHERE  (mn.val1 + mn.val2 + mn.val3 > 0)
	ORDER BY pt.id DESC

کامل کردن قسمت صحیح#

تا این قسمت می‌دانیم که عدد ورودی صفر نیست، اما ممکن است قسمت صحیح صفر باشد و مقدار اعشاری داشته باشیم. مانند 0.355
آنگاه جمله‌ی ما باید با منفی یا صفر شروع شود. اگر هم با صفر شروع نشود، حرف «و» اضافی انتهای رشته را حذف می‌کنیم. در مثال زیر بعد از اعداد شصت و ممیز چهار حرف «و» اضافه است که باید حذف شود:
شصت و ممیز چهار و صدم

IF @IntegerText='0'  
	SET @Str =  @Negative +  N'صفر'		
ELSE
	-- در صورت حذف نشدن => مثلا: شصت و ممیز چهار و صدم
	SET @Str = @Negative  + LEFT (@Str, LEN(@Str) -2)

بدست آوردن اعشار#

ابتدا بررسی می‌کنیم که مقدار اعشاری وجود دارد یا خیر؟ سپس در صورت وجود، ارزش مکانی مقدار اعشاری را براساس تعداد ارقام عدد و به کمک جدول DecimalTitle مشخص می‌کنیم. مثلا هزارم

IF LEN(@DecimalText) > 0
	BEGIN
		-- تعیین عنوان جایگاه اعشار بر اساس تعداد ارقام بخش اعشاری
		DECLARE @PTitle NVARCHAR(100)=
				ISNULL(
						(SELECT Title 
						 FROM @DecimalTitle 
						 WHERE id = LEN(@DecimalText)
						),
					'')

سپس مقدار اعشاری را به همین تابع ارسال می‌کنیم تا عناوین عددی آن مشخص شود و با ارزش مکانی اعشار و با عناوین قسمت صحیح ترکیب و به عنوان خروجی ارسال می‌کنیم.

	SET @Str +=
			N' ممیز ' +
			dbo.fnNumberToWords_Persian(@DecimalText) +
			N' ' + @PTitle;
	END
	RETURN @str
END
